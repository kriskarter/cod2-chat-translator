# CoD2 Smart Translation Engine V1 — технический паспорт

Статус: **v1.18.0 release candidate**. По правилам
[RELEASE_PROCESS.md](RELEASE_PROCESS.md) большой релиз обязан пройти ручную
проверку на Windows и в реальной игре до merge/tag/Release.

## Что реализовано

- F8 и F9 вызывают единый интерфейс SmartTranslationEngine.translate(request, provider, legacy_transform).
- Google Mobile и MyMemory, их тайм-ауты и fallback сохранены; API-ключ пользователю не нужен.
- Встроенный версионированный набор коротких игровых выражений версии cod2-smart-v1.0
  позволяет переводить GG/WP/NT/GLHF/AFK/BRB для RU/EN/UK без сети.
- Старые точные игровые выражения и проверенный транслит сохраняются, но опасные
  подстановки в любой текст не применяются принудительно.
- Локальные script hints различают кириллицу, латиницу и отдельные характерные буквы.
  Общая кириллица больше не автоматически объявляется русским языком.
- Намерение (command/question/warning/praise/inform) определяется дешёвой эвристикой.
- Короткий контекст до 4 сообщений того же автора за 8 секунд используется только
  локально для явного случая NS/no-scope. При смене карты буфер очищается.
- После MT проверяется сохранение чисел, HP, A/B, явных отрицаний, знака вопроса,
  @mentions, URL/IP и известных названий оружия. При неудачной нормализации допускается
  один повтор исходного сообщения без предварительного преобразования.
- При провале инвариантов F8 показывает оригинал с предупреждением; F9 не отправляет
  потенциально повреждённый перевод автоматически.
- Общий переключатель **Smart V1** возвращает классический алгоритм F8/F9 мгновенно,
  без переустановки. Переключатель сленга и стили Clear/Natural/Uncensored сохранены.

## Fast Mode — ускорение поступления входящего перевода

Отдельная локальная оптимизация без платных LLM и новых сервисов:

- Вместо одного последовательного worker используется **ровно два** потока
  перевода F8. Медленный ответ Google/MyMemory больше не задерживает всю
  очередь входящих сообщений. При этом очередь ограничена 50 сообщениями;
  не создаётся новый поток для каждой реплики.
- Оба потока разделяют ограниченный 400-элементный успешный translation
  cache и краткий контекст; доступ к ним защищён блокировками.
- Каждый worker повторно использует свои HTTPS-соединения к Google и MyMemory
  через requests.Session; никакого обмена объектами Session между потоками нет.
- Очередь сохраняет только структурированные сообщения CoD2. Время
  ожидания в очереди теперь входит в показываемое полное время перевода.
- Только в памяти хранятся агрегированные показатели задержки очереди
  и вызова переводчика: p50/p95 последних 64 сообщений. Сами тексты,
  никнеймы и история в измерениях не сохраняются.
- F9 имеет независимый путь с немедленным стартом при Enter;
  после доработки F9 надежно считывает UI-настройки до перехода в
  сетевой поток, не обращаясь к Tkinter из фоновых потоков.

Повторяемый *синтетический*, не игровой тест (24 сообщения, искусственно
75 мс на ответ сервиса, фиксированный burst) запускается:

    python tools/latency_benchmark.py --count 24 --fake-network-ms 75

При локальной проверке 13.11.2026 получено: p95 end-to-end
один worker = **1739 мс**, два workers = **914 мс** (уменьшение на
**47,4%**). Это показывает эффект параллельной очереди при искусственной
нагрузке. **Это не измерение реального Google, интернета, Windows/FPS**;
реальный выигрыш зависит от сервера, связи, размера чата и кэширования.
Синтетические показатели не заменяют игровой тест.

## F9 — исходящий перевод русского текста (13.11.2026)

Исправления для случаев «долго думает» и «не переводит»:

- Все настройки пары языков, стиля и Smart Engine считываются только в
  главном UI-потоке, до отправки запроса. Прежний доступ к Tkinter из
  рабочего потока создавал риск нестабильной работы в Windows.
- Постоянный диспетчер запускает не более двух F9-потоков и хранит
  не более одного ожидающего черновика. При следующем изменении текста
  старый ожидающий черновик заменяется новым, а Enter получает приоритет
  над устаревшим превью. Старые начатые HTTPS-запросы ограничены тайм-аутами,
  и их ответы не могут быть отправлены после изменения текста.
- Каждый поток использует собственную HTTPS-сессию Google/MyMemory,
  повторно используя соединение при последующих запросах.
- Успешные переводы кэшируются только в оперативной памяти, до
  128 записей, с учётом языка, исходного текста, стиля и Smart/Classic.
  Ошибки и неподтверждённые переводы не кэшируются.
- Если Google вернул перевод с нарушением тактических инвариантов,
  пробуется бесплатный MyMemory. Если и он нарушает смысл, ничего
  автоматически не отправляется.
- Для текущего запроса F9 теперь выводит время и источник перевода
  в строке состояния (Google, MyMemory, кэш, локально).
  При ошибке F9 показывает ошибку, приблизительное время ожидания и
  подтверждение «Ничего не отправлено». Текст сообщения не сохраняется
  в диагностические журналы.
- При переключении языков старый перевод признаётся неактуальным,
  даже если введённый текст остался тем же. Зависшее ожидание Enter
  перезапускается с новой языковой парой.
- Дебаунс ввода и существующие короткие HTTP-тайм-ауты не сокращены
  наугад: меньшее ожидание не должно оборачиваться большим числом отказов.
  Новых платных LLM и API-ключей нет.

Проверено локально: полный набор unit-тестов, сценарии F9
(переиспользование сессий, однотипные фразы, очередь черновиков,
передача параметров из UI, ошибки обоих провайдеров, безопасность
автоотправки, переключение языка). Не подтверждено: реальная
скорость и стабильность русского F9 в запущенной CoD2 на Windows —
требуется ручной RC playtest.

## Чего пока нет

V1 — лёгкий безопасный semantic frontend, **не обученная LLM**. Неизвестные фразы
обычно всё ещё переводит онлайн MT. Нет автоматического самообучения, embeddings,
модели смешанных языков, offline NMT и отдельных подписанных обновлений базы знаний.
Вычисляемый confidence — не калиброванная вероятность; safe=true означает лишь
прохождение небольшого набора инвариантов, а не гарантированный точный перевод.

Не собран лицензированный корпус реальных сообщений CoD2; оценка качества на
реальных языковых парах пока НЕ проведена. CPU/RAM/p95/FPS на Windows в игре
также ещё не измерены. Запрещено выдавать синтетические проверки за такие измерения.

## Безопасность и приватность

Сохраняется чтение только новых строк console_mp.log, фильтрация сообщений,
F8 overlay, F9 keyboard send и установка/обновление. Никаких DLL-инъекций,
обходов античита и правок памяти игры. В интернет передаётся только одна
отфильтрованная чат-реплика, а не лог целиком, ник отправителя или историю
сообщений. Никакая телеметрия или AI API не добавляются.

## Проверки и критерии выпуска

В рабочем каталоге с установленными зависимостями:

    python -m unittest discover -s tests -v
    python tools/smart_quality_check.py
    python -m compileall -q smart_engine.py app.py outgoing_chat.py translation_fallback.py

Offline quality check: 32 синтетических примера с подставным ответом MT,
каждый помечен SYNTHETIC. Измеряется только выполнение защитных правил.
Желательный результат: все пройдены, unsafe_accepted=0 и valid_rejected=0.

После зелёного Windows RC CI пользователь проверяет в игре:

1. F8: GG, WP, NS, 1hp, rush B, транслит, смешанные языки, ошибки и мат.
2. F9: RU→EN, EN→RU, UK→PL; Enter до окончания перевода; Esc/F9 отменяют.
3. Повреждённый перевод F9 не отправляется; корректный уходит ровно один раз.
4. Smart V1 ON/OFF без перезапуска; сравнить Classic с прошлой v1.17.4.
5. Offline/slow Google/MyMemory fallback и burst сообщений; смену карты.
6. Ники и форматирование, серверы/mod-пути, F8/F9/F10 и оверлей.
7. Измерить CPU/RAM, latency p50/p95 и FPS на старом ПК.

Пока реальный ручной playtest не пройден, PR остаётся draft и
релиз v1.18.0 НЕ выпускается. При регрессии включить Classic и
зафиксировать текст примера, язык, ожидаемый смысл и фактический результат
без публикации персональных данных.
