# Premium Game UI — архитектурный эксперимент

База `f55bb7d5700a2ad81c555e4505416e1a4589a88d`; независимая ветка
`experiment/qt-premium-game-ui`. Нынешний `app.py` и весь Tk RC сохранены.
Оба кандидата запускаются отдельно и **не являются новым рабочим приложением**.
В них используется только сравнимый демонстрационный набор из трёх серверов.
Продуктовый запуск, конфигурация, hotkeys и UDP не переключены на него.

## Проверенное сравнение

Настоящие кадры Qt offscreen с software backend, одна машина и одинаковые
1366×768 / 900×620: [Quick 1366](images/qt_experiment/quick_1366.png),
[Widgets 1366](images/qt_experiment/widgets_1366.png),
[Quick 900](images/qt_experiment/quick_900.png),
[Widgets 900](images/qt_experiment/widgets_900.png).
Скриншоты получены после запуска программ, а не из эталона.
`python -m qt_experiment.measure` создаёт пять отдельных процессов на кандидата;
метрика включает запуск Python, Qt и первый кадр. Данные одного прогона:

| Показатель | Qt Quick | Qt Widgets |
| --- | ---: | ---: |
| Холодный процесс + первый кадр, медиана | 494,0 мс | 389,7 мс |
| Наблюдаемый пик RSS, медиана | 91,8 МиБ | 73,4 МиБ |
| Диапазон запуска пяти прогонов | 406,9–523,6 мс | 374,4–391,3 мс |
| Аппаратный GPU / CoD2 FPS | не измерено | не измерено |
| p95 настоящих действий в полном приложении | не измерено | не измерено |

При одинаковом контрольном наборе Quick выразительнее сохраняет компоновку,
позволяет декларативно связывать состояния и не требует сборки огромных
растров на изменение размеров. Widgets расходует меньше RAM и быстрее даёт
первый кадр. **Основным кандидатом остаётся Quick**, но производственный
выбор нельзя считать окончательно подтверждённым до переноса рабочего цикла
и измерений на Windows во время CoD2. WebView2 пока не требуется.

## Слои и геометрия

* Панорама: отдельный существующий `premium_hero.png`, логотип:
  `premium_logo.png`; рисуются как самостоятельные слои. Никаких невидимых
  областей поверх полной картинки эталона.
* Функциональная область: две колонки с коэффициентом 43:57, 14 px между ними,
  17 px внешний отступ; F8 и F9 занимают равные высоты.
* Навигация: 48 логических px; нижняя полоса: 82 px; шапка: 135–190 px
  по фактической высоте клиентской области. Карточки и монитор не создают
  общей вертикальной прокрутки.
* Панели: внешний бронзовый контур 1 px, внутренний контур с отступом 4 px,
  тёмный графитовый центр; закругление 9 px. Изображения карт загружаются
  отдельно и получают локальную альфа-композицию. Девятисегментное
  масштабирование рамок пока не реализовано: текущие рамки векторные.
* При логической ширине менее 1100 px карточка сжимает клавишу и оставляет
  статус в тексте; это сохраняет переключатель в самой клавише.
* Цвета: фон `#111313`, графит `#1a1c1b`, бронза `#aa8854`, янтарь
  `#d4a75e`, тёплый текст `#f5e7c9`, зелёный статус `#b0db84`.
  Шрифт: Segoe UI с системной подстановкой. Все три локали и шрифтовое
  покрытие ещё требуют проверки; прототип подписан на русском.
* Кнопки имеют normal/hover/pressed; F8/F9, overlay, smart и выбор сервера
  действительно изменяют состояние. Точки входа `add_server`, `refresh`,
  `connect` испускают события, пока не подключены к рабочему контроллеру.
* Цветовые коды игроков преобразуются через существующий `color_runs`;
  HTML-спецсимволы экранируются. Статусы limited/offline и отсутствие ответа
  остаются различными; выбор по адресу сохраняется при обновлении другой строки.

## Граница ядра и обязательный перенос

`PrototypeState` — независимая модель представления. `Monitor` и `Snapshot`
из `server_monitor.py` уже свободны от Tk; их callback следует доставлять
в Qt UI-поток через queued signal. Нельзя запускать UDP, перевод или запись
истории непосредственно в QML. Сигналы `action` сейчас означают **только
намерение**, никакие продуктовые действия пока не подтверждены.

`ControlApp` в `app.py` ещё создаёт `tk.StringVar`, `OutgoingChatController(root=...)`,
`OverlayWindow(root, ...)`, `FriendNotice`, `LogTailer`, два TranslatorWorker,
горячие клавиши через `root.after` и очередь UI-событий. Перенос должен
сначала вынести настройки и состояние в обычные Python-объекты; затем
контроллеры F8/F9/F10 и жизненный цикл оверлея переводятся на Qt event loop,
с сохранением существующих файлов пользователя. Нельзя объявлять Qt RC,
пока эти зависимости не устранены и цикл не прошёл Windows/CoD2.

Инвентаризация основных обработчиков перед переносом:

| Действие | Текущий обработчик | Статус Qt |
| --- | --- | --- |
| F8, F9, F10 | `toggle_enabled`, `OutgoingChatController`, `toggle_overlay_hotkey_visibility`, `poll_global_hotkeys` | только сигналы F8/F9 |
| Приём лога и перевод | `LogTailer`, `TranslatorWorker`, `process_ui_queue` | не подключено |
| HUD, тест, очистка | `OverlayWindow`, `test_overlay`, `clear_overlay` | только состояние полосы |
| Монитор | `Monitor`, `ServerPage.update_snapshot`, `PremiumHome.update_snapshot` | DTO и обновление строк; живой UDP не подключён |
| Серверы | `ServerPage.add/edit/remove/favorite/connect/copy` | сигналы add/connect; прочее не подключено |
| Друзья | `ServerPage.add_friend`, `_server_friend_update`, `FriendNotice` | не подключено |
| Профили и логи | `_refresh_server_profiles`, `show_server_settings`, `choose_log` | не подключено |
| Knowledge / статистика | `_show_knowledge_dialog`, `_knowledge_stats`, `request_stats` | не подключено |
| Обновление | `check_updates`, `_launch_updater` | не подключено |
| Вкладки и диалоги | `wwii_dashboard.py`, `premium_*`, `app.py` | только прототип Home |

Остальные действия и модальные окна потребуют отдельной построчной сверки
перед отключением Tk. Никакой интерфейс с заглушками не должен заменять
установленный RC.

## Лицензии, упаковка и границы проверки

PySide6 6.8.3 установлен только для эксперимента; его не добавляли в
`requirements.txt` или Inno Setup. Qt for Python распространяется под
LGPLv3/GPLv3 либо коммерческой лицензией
([официальная документация](https://doc.qt.io/qtforpython-6/)); условия
динамической компоновки, уведомления и доступность библиотек должны быть
проверены до релиза. Qt описывает PyInstaller и `pyside6-deploy` как варианты
упаковки, а для QML сборка должна включить импорты и плагины
([документация деплоя](https://doc.qt.io/qtforpython-6/deployment/deployment-pyside6-deploy.html)).
Новые художественные файлы в эксперимент не добавлены. Происхождение
существующих ресурсов задокументировано отдельно в `ASSET_PROVENANCE.md`;
это не заменяет лицензионную проверку конкретных файлов перед релизом.

KRIS-KARTER сейчас офлайн. Нативная Windows-проверка, матрица 27 сочетаний,
GPU, игра, installer, обновление/удаление и отладка оверлея не выполнены.
Скриншоты и RSS выше относятся только к Linux offscreen; это не Windows CI.
