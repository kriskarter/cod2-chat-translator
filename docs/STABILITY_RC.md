# v1.22.0 RC — стабилизация интерфейса PR #8

Кодовая редакция: `c3f9105c85a78a2e8a4ac43c249498cbb19702e5`; коммит снимков и этого отчёта следует за ней. PR остаётся draft; stable не затронута. RC-установщик публикуется отдельно как prerelease.

## Установленные причины и изменения

- Профиль старого кода `81b72d6`: 49 синхронных вызовов `MetalCanvas._redraw` заняли 41,25 с суммарно в главном потоке на нагруженном VPS, максимум одного вызова 2,59 с. Pillow пересоздавал полноразмерные композиции во время Configure. Теперь Pillow выполняет один фоновый worker, отменяет устаревшие задания; Tk PhotoImage создаётся только в UI-потоке. Повторный инструментированный прогон показал 74 коротких вызова постановки задания с суммой 11,9 мс. Это измеряет перенос работы из UI-потока, не общее время отрисовки.
- Главная содержала `pack/pack_forget` scrollbar в обработчике Configure: изменение ширины порождало новую компоновку. Полоса теперь размещается поверх стабильной ширины, а изменения размеров объединены таймером.
- Начальная геометрия бралась от всего экрана и заходила на панель задач Windows. Теперь используется доступная область Win32 и запас под системную рамку; высота баннера и блоков зависит от клиентского окна. Отложенные обработчики отменяются при уничтожении интерфейса.
- Для DPI >=125% строка поиска и действия на странице серверов разнесены, чтобы не обрезать «Обновить». Переключатели F8/F9, UDP-монитор и пользовательские настройки оставлены рабочими. Значок друзей заменён читаемым силуэтом группы, статус готовности учитывает игру и журнал.
- Кеш готовых кадров ограничен четырьмя размерами, исходные изображения декодируются один раз там, где это оправдано, дублированные полноразмерные копии стали освобождаться. Художественные изображения F8/F9 слегка приведены к графитовой палитре.

## Визуальная приёмка

Настоящие снимки запущенного приложения под Linux/Xvfb находятся в `docs/images/stabilization_rc/` и не выдаются за Windows. `100/` и `150/` содержат Home, Servers, Translation, Overlay, Settings, Knowledge, Stats, History и About. `125/` и `wide/` содержат Home и Servers. Диалоги, код которых не менялся, сохранены в `docs/images/final_art_rc/xvfb_dialog_*.png`.

| Клиентское окно / Tk scale | Home / viewport | Прокрутка Home |
| --- | ---: | --- |
| 1366×688 / 1.33 (~100%) | 472 / 476 px | нет |
| 1366×688 / 2.0 (~150%) | 477 / 491 px | нет |
| 1536×784 / 1.65 (~125%) | 542 / 557 px | нет |
| 1920×970 / 1.33 | 680 / 695 px | нет |

На 100% видно пять строк живого списка игроков. Обновление серверов на снимках получено реальными UDP-запросами; карта, состав и пинг меняются. Подписи длинной карты доступны через подсказку. На 150% дополнительные серверные настройки прокручиваются внутри страницы, а главная помещается целиком.

По сравнению с утверждённым эталоном цельная панорама, две разные сцены F8/F9 и металлический материал сохранены. Декоративный ящик и каска снизу не возвращались. Отличия остаются: экспертные страницы плотнее эталона, рамки и выделение строки местами грубее, солдат в баннере показан со спины, а переключатели имеют более утилитарный вид.

## Проверки и показатели

`pytest -q`: 222 passed, 1 skipped. Полный Xvfb smoke при 1366×688 прошёл отдельно на 100% и 150%: 8 страниц, F8/F9, настройки, прокрутка игроков, RU/UK/EN и отсутствие обрезания кнопок. Windows CI запускает unit tests, смысловую проверку Smart Engine, PyInstaller и Inno Setup. Результат точного итогового SHA указан в PR.

Один последовательный Linux/Xvfb сценарий на загруженном VPS: запуск; изменение 1366→1200→1366; Servers→Home; обновление мониторинга. Таймер UI запланирован каждые 25 мс. Сравнивать эти одиночные wall-времена с Windows нельзя; нагрузка VPS менялась.

| Метрика | исходный `81b72d6` | оптимизированный код |
| --- | ---: | ---: |
| Запуск | 26,79 с | 10,88 с |
| Пиковый RSS после сценария | 146,9 MiB | 175,7 MiB |
| CPU за сценарий | 19,70 с | 13,26 с |
| Медиана задержки UI | 63,5 мс | 156,2 мс |
| 95-й процентиль | 1881 мс | 2411 мс |
| Максимум | 6673 мс | 4597 мс |

Уменьшение CPU и хвоста максимальной задержки сопровождается ростом памяти примерно на 29 MiB; медиана и 95-й процентиль в этом прогоне не улучшились. Цель обычных действий <100 мс **не подтверждена**. GPU, холодный запуск на Windows и влияние одновременно запущенной CoD2 не измерены.

Авторизованный Windows-компьютер KRIS-KARTER офлайн. Поэтому нативные установка, DPI 100/125/150%, перемещение окна, F8/F9/F10 в игре и нагрузка с CoD2 остаются непроверенными. Windows CI подтверждает сборку и тесты, но не визуальную приёмку установленной программы. Переход на Qt не сделан: текущий слой Tk теперь изолирует тяжёлую композицию без переписывания переводчика, однако нативные показатели нужны до окончательного выбора архитектуры.
