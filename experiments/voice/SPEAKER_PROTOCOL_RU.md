# CoD2 1.3 — эксперимент по ID говорящего

## Проверенные исходники (не CoD4)

1. [janost/vcod, docs/research/cod2-protocol.md, §1.7](https://github.com/janost/vcod/blob/main/docs/research/cod2-protocol.md) — анализ Mac CoD2 1.3: сервер отправляет OOB-голос с заголовком FF FF FF FF, строкой v и количеством пакетов; для каждого пакета указывается номер говорящего, длина, аудиоданные.
2. [STiXzoOR/cod2-silicon, src/PC/server_mp/sv_voice_mp.c](https://github.com/STiXzoOR/cod2-silicon/blob/main/src/PC/server_mp/sv_voice_mp.c) — серверный SV_SendClientVoiceData() отправляет talker, dataSize и data. Встречаются варианты команды v и voicePacket.
3. [callofduty2x/CoD2x, src/shared/cod2_client.h](https://github.com/callofduty2x/CoD2x/blob/main/src/shared/cod2_client.h) и [cod2_player.h](https://github.com/callofduty2x/CoD2x/blob/main/src/shared/cod2_player.h) — экспериментальная схема CoD2 1.3 Win32 clientInfo[64]: адрес 0x015CF994, структура размером 0x4B8, поля infoValid/nextValid/clientNum/name[32].

Это **обоснование тестовой реализации**, не свидетельство успешного захвата настоящих пакетов на компьютере пользователя.

## Настройки безопасности

По умолчанию обе новые функции **отключены**. Их не следует включать в основной переводчик без отдельного успешного теста.

**Получать ID говорящего из UDP (Windows UAC)**: после согласия пользователь запускает отдельный повышенный процесс через диалог Windows. Он слушает только входящий IPv4, строго отбирает голосовые UDP-пакеты CoD2, сохраняет только время и номер игрового слота; исходное аудио и сетевые пакеты не записывает. Адрес сервера в локальном файле представлен усечённым хэшем. Нет сетевых отправок, нет DLL, нет перезаписи памяти. Сбор останавливается при отключении или закрытии программы. Нужны права администратора, поддержка сырого IP capture в Windows; блокировки антивируса/сетевого драйвера возможны.

**Ники из памяти CoD2 1.3 (чтение)**: отдельное согласие на чтение таблицы clientInfo из единственного процесса CoD2MP_s.exe в выбранной игровой папке. Доступ только PROCESS_VM_READ и QUERY_LIMITED_INFORMATION. Ник принимается только когда схема/номер слота пройдут проверки; неверная структура ничего не выдаёт. **Некоторые античиты могут запрещать даже чтение памяти игры**: только для теста без активного античита. Права администратора для чтения ников не запрашиваются. Никаких гарантий совместимости с альтернативными сборками CoD2.

## Как работает надпись

* Уникальный номер говорящего в нескольких близких голосовых фреймах + успешно прочитанная проверенная таблица: реальный ник, например Pirat.
* Уникальный номер без подтверждённого имени: «Игрок #12 (ник неизвестен)».
* Несколько собеседников в интервале, отсутствие пакетов, неизвестный формат: «Игрок (ник неизвестен)». **Никаких догадок по соседнему текстовому чату и никакого распознавания личности по голосу.**

## Как провести первый тест

1. Распаковать экспериментальный Windows ZIP, закрыть старую программу, запустить CoD2 в обычном привычном полноэкранном режиме.
2. В прототипе сначала включить **только «Получать ID говорящего из UDP»**, подтвердить согласие и UAC. Галочка снимков экрана не нужна.
3. Нажать «Слушать игру». Дождаться входящей речи одного игрока. Проверить статус сетевого пробника: listening либо сообщение raw_socket_unavailable/capture_failed.
4. Убедиться, что в журнале появляется «Игрок #N». Если не появился, передать локальные (без аудио) файлы voice_packet_probe_*.jsonl и voice_nickname_research.jsonl. Только после этого можно доверять реальным packet offsets.
5. Если номера заработали, **лишь в тестовой сессии без античита** отдельно включить «Ники из памяти CoD2 1.3 (чтение)», проверить совпадение имени с игровым HUD.

Прототип не меняет main, не выпускается как stable. Время распознавания Whisper/Vosk остаётся отдельной проблемой; получение никнейма не должно его замедлять.
